# Revising a delivered supplied-image review for platform media

Use when an unapproved, already delivered reference-workflow photo draft needs a compatible proportionally resized derivative while retaining its job, captions and targets. This is not attachment intake, target reduction, or post-publication recovery. The previous review does not approve changed image bytes. If any approval receipt, schedule, POST_LOG, platform attempt or uncertain remote outcome exists, stop and use [publication recovery](../multi-platform-publication-recovery/SKILL.md); do not reset it.

1. Inspect the installed exact-review, supplied-image QA and publication gates before changing a Sheet URL. In the verified path, the reviewer compared **every** selected platform asset SHA256 with the single delivered preview SHA256. Assigning a TikTok-only derivative would fail that gate even if the artwork were visually equivalent. If this remains the contract, use one compatible derivative as the revised common asset, or implement and test an explicit per-platform review binding; never weaken hash equality or silently change one platform's media. Check the platform's actual media validator, decoded dimensions and public bytes.
2. Under existing worker/review locks, require a completed verified supplied-image draft, a genuine original delivery receipt, DRAFT / WAITING_APPROVAL / MANUAL in Sheets, and matching frozen target/caption/media rows. Inspect read-only ledger, schedule and POST_LOG for approvals and attempts. Preserve the original PNG and JPEG bytes, import proof and request/job ID. Require a provenance record binding the derivative to the original hash, job, local hash and approved public URL; compare public JPEG hash and decoded visual/aspect-ratio similarity, rejecting crops or artwork changes. A proportional resize can change dimensions and SHA256 while preserving content; an equality-of-dimensions QA rule falsely rejects that case. Replace it only with a bounded aspect-ratio plus visual comparison and negative crop/artwork tests, retaining hash-bound human/vision review.
3. Archive the complete original state, visual-review evidence and derivative provenance before mutation. Invalidate current review eligibility durably **before** any external Sheet write. Update only the existing job's intended media URL fields; reread the whole relevant row and verify captions, hashtags, targets and status unchanged. Recheck attempts before finalization. Bind the new state and supplied-image review to the derivative SHA256 without overwriting the original review history. On uncertain Sheet write or readback mismatch, leave the job blocked for reconciliation; never auto-rollback or retry publication.
4. Claim a fresh preview for the revised exact binding and each authorized owner channel, send through the actual messaging tool and persist/validate the raw receipt. A URL upload or old preview receipt is not revised delivery. Preserve independent channel claims; UNKNOWN/CLAIMED is not permission to resend. Run the **unchanged production exact-review gate** against fresh Sheets, downloaded asset hashes and the new delivery receipt. Offline unit success alone does not prove that gate accepts the revision.
5. Ask for a new authenticated exact-job approval through the installed owner-command bridge only after revised review succeeds. Do not call a publisher, forge an inbound actor, or treat the earlier creation/publish-intent message as approval of the new bytes. Verify the durable approval and then each requested platform's ledger/owned-post URL through the publication-recovery procedure. Passing quality, delivery and read-only exact-review with NO_DURABLE_RECEIPT still means no approval or publication; do not describe the owner command as exercised.

Completion: original asset/hash and prior receipts preserved, revised public media SHA and visual review, same job with exact Sheet readback, new genuine delivery receipts, passing installed exact-review gate, and explicit approval/publication state by platform. A revision complete but awaiting a fresh owner command is a draft, not publication.
