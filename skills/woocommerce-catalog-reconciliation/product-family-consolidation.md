# Product-family consolidation

Use only when the owner explicitly authorizes combining existing product families. Follow the main skill’s backups, immutable plans, shared lock, exact readbacks and uncertain-write recovery. A prior merge does not authorize future merges.

1. Freeze identity and history before deciding how to migrate. Capture both parents, all children, SKUs, attributes/defaults, prices, stock, media, SEO, public URLs and order-item references to every affected parent/variation ID. Check the installed order storage rather than assuming a parent has no history. Prefer a canonical existing parent. Reparent existing variations through supported WooCommerce CRUD only when the reference analysis establishes safety; otherwise retain historical children and plan a supported alternative. Never force duplicate SKUs or rewrite old orders to make the migration fit.
2. Capture child objects before changing parent attribute definitions. Build the exact final option × transaction matrix, including each preserved or explicitly new child ID. Owner-confirmed spelling aliases can normalize target options without merging distinct models. If source A:H must remain unchanged, persist the approved alias separately; validate against that normalized target contract rather than editing source text or relaxing all identity checks. When two source rows map to one canonical parent, retain each row’s independent prices and fingerprint and record the shared parent only in authorized metadata.
3. Plan derived fields as well as setters. A parent title/attribute change can regenerate child names, post titles, summaries and URLs. Validate their exact expected new representations and compare remaining fields unchanged; do not classify a legitimate regenerated title as corruption or blanket-ignore child copy. Test wrong price, SKU, summary, URL and custom metadata cases. If the complete intended write already landed, recover read-only using the main skill’s checkpoint procedure.
4. Keep the old listing public until the combined product passes all combinations in real desktop/mobile controls and the redirect is ready. Inspect existing redirect facilities first; an installed RankMath redirection API can provide exact-source permanent redirects without changing web-server configuration or unrelated snippets. Verify each changed old URL returns 301 to the canonical URL, followed by 200 without a loop. Then retain the superseded parent as a nonpublic historical record, not a permanent deletion. Verify retirement did not change protected stock: saving a childless variable parent can derive `outofstock`. If that exact side effect occurs, preserve the receipt and use a guarded supported WooCommerce data-store operation to restore only the attributable stock field; reject intervening drift and recheck the whole protected record. Do not add stock to a blanket ignore list.
5. Check the canonical tag, public search, every shop page, relevant stored internal links and the product sitemap. Require exactly one public family card and only the canonical sitemap URL. Distinguish sitemap contents from route health: a working RankMath query sitemap does not prove pretty XML endpoints work. Report a pre-existing pretty-route failure separately; do not claim it repaired or silently broaden a scoped consolidation into global routing changes. Use the price-display skill’s pagination and control-reset checks.
6. Persist website and history verification before mirroring source-row mappings. Read back each metadata row and compare all protected source cells/formulas. Finish with fresh read-only verification of the final matrix, archived parent, order references, redirects and preserved media. Refuse replay of an already-checkpointed migration; recovering missing metadata or a report must not migrate children again.

Completion: canonical parent and final child IDs/prices, retained historical records, unchanged order references, one public listing, verified old-URL redirects, canonical/sitemap evidence with route caveats, exact multi-row metadata readback, and explicit limits on any unverified gate.
