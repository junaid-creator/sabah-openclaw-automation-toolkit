# WooCommerce catalog reconciliation

Use for source-to-catalog synchronization or recovery of an existing catalog mutation. Audit alone does not authorize writes. For access evidence use [google-sheets-readiness](../google-sheets-readiness/SKILL.md); for transaction/discount semantics, Elementor badges and real-browser price checks use [woocommerce-price-display-audit](../woocommerce-price-display-audit/SKILL.md). Do not infer standing publishing, image-generation or discount policy from an earlier one-time approval.

For an explicitly authorized merge of published product families, read [product-family consolidation](product-family-consolidation.md) before freezing the migration plan. It adds order-history, retirement, redirect and multi-row mapping gates to the common safeguards below. When turning a one-time synchronizer into owner-approved CHECK/ADD/UPDATE jobs, read [approved row jobs](approved-row-jobs.md) for identity reservations, exact previews and phase-safe recovery.

1. Read the complete current source range, schema and catalog, including drafts and variations. Exhaust pagination; do not freeze reads to an old last row. Detect changed row count/schema and require replanning rather than silently omitting new rows. Compare source inputs separately from tracking metadata: an old error note or saved fingerprint does not override corrected source cells. Match recorded IDs with SKU/identity evidence; missing SKUs and generic family names do not prove a new product. Block conflicting option/transaction prices and unresolved one-row-to-multiple-product mappings without blocking unrelated authorized work.
2. Freeze an immutable field-level plan with source inputs, parent/child IDs, exact before/after values and protected fields. Keep source, target and plan fingerprints distinct. Preserve media, stock, SEO, status and unrelated copy unless separately authorized; any price-bearing copy changes should be surgical. Match old amounts semantically across decimal/thousands formatting, require unambiguous option/transaction attribution, and compute replacement spans from the original text so one replacement cannot cascade into another. An old amount rendered as `100.00` must not evade a check for `100`; block ambiguous copy rather than leave stale prices. Use the existing shared product lock for every writer, compare live source and target before mutation, and recheck after verification. A local lock cannot make Sheets and WooCommerce a distributed transaction or prevent remote human edits; report that residual race.
3. Before production mutation, take protected fresh database, scoped catalog/meta/term, snippet and source/formula snapshots. Verify compressed backup integrity and, when restore readiness is required, restore to a separate private database with networking disabled; compare relevant records/checksums and stop that test server. Never test restoration over production. Snapshot/file existence alone is not restore proof. Test the actual mutation adapter with representative records, then use a bounded live canary; mocks do not establish full WordPress integration behavior.
4. For a local variation-attribute rename, capture child objects and their original attributes **before saving the renamed parent**: WooCommerce may filter unknown child keys when subsequently reading them. Preflight parent/child key collisions and the exact child set. Rename the parent definition and matching default key, migrate existing children through supported WooCommerce setters, then synchronize derived data. Preserve each child ID, technical option value and transaction mapping. Do not recreate variations to change labels. Explicitly account for attribute order when equal positions can reorder selectors.
5. Verify planned fields plus protected data, not only the fields sent. Compare the union of old/new record, data, post and metadata keys, including URLs, so added keys cannot evade an old-keys-only comparator. Check effective prices on no-op rows too: matching regular_price with empty sale_price does not validate a divergent effective price. Keep promotion-aware decisions explicit rather than silently overwriting discounts. WooCommerce regenerates child attribute_summary and post_excerpt after attribute changes. Derive the exact expected summary from the expected local option values, validated parent labels and actual child ordering; compare both fields. Reject stale labels, wrong values, extra text and blanks instead of adding a blanket ignore. Reverse migration can produce the same semantic options in a different order from the historical summary; validate the exact supported regenerated reverse representation. Test forward/reverse adapters with realistic regenerated summaries, not mocks that leave them unchanged. Taxonomy attributes need their own term/label contract rather than blindly applying the local-attribute derivation.
   For authorized draft publication and saved-receipt replay, read [draft publication validation](draft-publication-validation.md) when freezing the plan and before comparing derived slugs, parent/child URLs and Elementor cache metadata. Validate only the narrow planned representations; do not blanket-ignore URLs or metadata.
6. If a write times out or verification stops after mutation, preserve the checkpoint and inspect the live result before any retry or rollback. A completed mutation rejected solely by an over-strict derived-field check can be recovered without another remote write: first establish that the exact planned fields and protected data match, fix the precise validator with negative regressions, then run an explicit **read-only recovery** that checks source, combinations and frontend and rereads source/target for concurrent drift. Only a complete intended result receives a local VERIFIED receipt, retaining the previous checkpoint. Partial results or unexplained changes remain intervention-required. Never reset state to force replay; guarded inverse writes require attributable current values and must preserve intervening edits.
7. Persist verified website results before mirroring source metadata. Failed/uncertain metadata writes remain SHEET_PENDING; read back before retrying and never repeat product mutation to repair the mirror. Completed-run retries must perform fresh source/catalog/frontend checks while skipping writes; retain the original synchronization timestamp and record revalidation separately so metadata recovery remains stable. Verify no-op rows as well as changed rows; do not mark blocked drafts synchronized merely because their current source fingerprint was recorded.

Completion evidence: all source rows classified, preserved parent/child identities and protected fields, verified intended values and public selectors, exact metadata readback, explicit draft/identity blockers, and a post-run dry run with no further authorized changes. Prove replay safety with fresh read-only revalidation and unchanged catalog/source snapshots. Report database restore tests, mock adapter tests, live canary/browser checks and any cart tests separately. Do not install an unattended scheduler as a side effect of a monitored synchronization request.
