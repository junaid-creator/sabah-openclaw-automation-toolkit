# Draft publication derived-field validation

Read when planning or verifying authorized publication of an existing draft, or revalidating its saved receipt after a browser check. Apply the [main catalog procedure](SKILL.md) for immutable plans, backups, protected-field comparisons and read-only uncertain-write recovery. This branch grants no publication authority.

For authorized draft publication, also validate publication-derived fields before treating a changed record as corruption. A previously blank parent slug can be generated on publication, changing the parent permalink and each child URL without changing the child record. Freeze the expected slug/public URL; validate each child URL against that parent and its unchanged attribute query pairs, then compare the remaining child data exactly. Never blanket-ignore URLs. Preserve an existing nonblank slug unless its change is explicitly authorized and planned with old-URL redirects. First public rendering can add Elementor’s empty `_elementor_page_assets` cache: if absent before, accept only the observed empty representation (`['a:0:{}']` in raw metadata and `[]` in the corresponding Woo `meta_data` value). If the cache already existed, compare the original raw and Woo metadata entries exactly; do not strip it only from the actual result and compare against an unfiltered baseline. Compare every other custom/SEO metadata entry unchanged. Reject unexpected slugs, child queries, nonempty cache and SEO changes in negative tests. Use the same narrowly validated derived-field handling for saved-receipt replay comparisons; otherwise a successful browser check can make the next replay falsely report drift.
