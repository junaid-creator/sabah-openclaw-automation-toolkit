# Published-image verification

Read when a publication workflow requires image proof beyond its post ID and owned-post URL, especially after a mismatch or incomplete scoped verification. Apply the [main recovery procedure](SKILL.md) for approval binding, duplicate prevention and reporting; this branch does not authorize another submission.

Where a workflow additionally requires published-image matching, a generic ledger status derived from post ID and URL does not satisfy that stricter gate. Inspect the scoped verification record and read-only comparison evidence separately: a failed check may mean missing media URL, disallowed CDN host/redirect, fetch/decode failure, aspect-ratio difference, or pixel difference. Also check the comparator’s input contract before changing thresholds: asset receipts may be `{sha256, visual:{ratio,pixels}}` while the comparator expects the nested visual object. A swallowed key error can report a false mismatch; unwrapping that object restored matching in a verified recovery. Test both a matching wrapped receipt and a genuinely different image, retaining CDN restrictions and existing thresholds. Re-run only read-only owned-post/media retrieval and comparison. Platform JPEG byte hashes can differ while the required visual features match; do not substitute byte equality for the workflow’s visual contract. Do not infer the wrong image from a single false result, downgrade confirmed publication, reset the scoped gate, or submit another post. Once the required read-only checks actually pass, an authorized verification-only reconciliation may update the scoped gate with a backup and audit event; preserve original approval data, post IDs, attempts and other targets, and compare protected rows before/after.
