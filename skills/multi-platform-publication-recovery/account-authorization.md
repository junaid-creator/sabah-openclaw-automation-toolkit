# Account authorization preflight and repair

Use when app permissions were approved but an existing account token still cannot read owned posts, or when the owner separately authorizes repair of the token-exchange helper. Permission diagnosis is not consent, token replacement, or publication approval.

## Diagnose without rotating credentials

1. Identify the installed API family, token store, identity pin, request transport, OAuth helper and refresh timer together. Inspect helper effects before calling a nominal preflight: a client token accessor may refresh and write automatically; a probe may save account pins or URL properties. For read-only inspection, use the existing non-refreshing request transport with the saved token, not those convenience wrappers. Report only expiry, grant names and identity comparisons, never credential values.
2. For the TikTok Business Accounts adapter, compare the saved account pin against live `tt_user/token_info/get/` (app and creator identity plus scope) and `business/get/` (company username). The token-info POST is a read operation, not a token exchange. Keep app-portal approval, account-holder grants, token validity and actual endpoint access as separate evidence. A valid token and matching account can still lack newly approved permissions.
3. Make only the authorized number of owned-media requests through `business/video/list/`, with no implicit retry. Missing live grants plus a 40130 response support an account-consent blocker, but do not prove consent alone will resolve every endpoint issue. Do not substitute developer Content Posting authorization for Business Accounts authorization. Preserve completed platforms and stop at the specified manual-consent boundary.
4. No local submission row is not proof of remote absence. A successful token-validation page also is not a complete job duplicate check: reconcile receipts, remote IDs and the relevant owned-media coverage separately before preparing a new publication approval.

## Repair only when authorized

1. Back up the helper, working token pair, account pin and app credentials privately; verify byte equality without displaying secrets. Inspect the actual refresh service and use its shared token lock so a concurrent refresh cannot overwrite the replacement. Keep existing-token refresh usable even when the newly requested read grant is absent.
2. Before generating state or a short-lived code, compare the helper’s **full authorization URL contract** (host/path, app ID, redirect, requested permissions and token-exchange API family) with the existing app’s portal-generated **account-holder** URL. A matching registered redirect and approved app permissions do not prove a locally constructed developer-Login/Content-Posting URL is the Business Accounts authorization flow, or that a similarly named `video.list` scope maps to Business Get Account Media; resolve mismatches against the portal and live Business endpoint contract before consent. Then inspect the exact callback: a reachable homepage is insufficient. Verify the dedicated path has no redirect, preserves the query in the browser address bar without external page resources, and has appropriate caching/referrer controls. A dummy-query HTTP 200 and headers prove only the public response, not that origin, proxy/CDN or analytics logs suppress query values; audit those separately before marking readiness true. When the agent cannot read root-owned live configuration, an authorized administrator’s scoped report of the effective exact-path include/location, logging directives, no-upstream behavior, config validation and dummy-marker log search can close the origin gate; label it administrator-reported rather than agent-inspected. A negative search covers only named log locations, not all provider-side retention; distinguish owner-reported edge controls from independently observed controls. If a dedicated route is needed, prepare the minimal host-specific change and verify deployment plus exact portal registration. Do not install it on a convenient local nginx host without establishing that host serves the callback domain.
3. Stage exchanged tokens privately instead of writing the active token file. Validate the candidate’s app, pinned account, username, required live grants and successful owned-media read before atomic promotion. Bind one-time state to app/account/redirect with an expiry; mark an exchange in flight before sending and never blindly replay an ambiguous exchange. Hidden terminal input must fail closed if getpass falls back to echo. Sanitize transport errors and reject credential-bearing redirects.
4. Preserve a verified pre-exchange backup, use the shared lock through validation/promotion, and restore old local bytes on failed promotion. State the limit: local rollback cannot reverse provider-side grant revocation or guarantee an old token remains remotely valid after consent.
5. Test with temporary credentials and mocked network calls: wrong/expired/reused state, denied or expired code, wrong app/account/username, missing grants/token pair, failed owned-media read, backup failure, promotion failures before and after replacement, no replay, private-file enforcement, credential-safe output, and refresh compatibility. Assert the old active token remains unchanged during every candidate validation call. Mock success proves these local guards, not successful live OAuth.

## Completion and handoff

Report separately: helper repaired, tests passed, callback syntax checked, callback deployed/security verified, portal redirect matched, consent completed, candidate read verified, token promoted, and publication readiness. Before recording callback readiness, re-parse the private portal URL against the installed helper’s app, redirect and full scope set without displaying or opening it; write the private readiness record only after the public dummy probe and scoped origin/edge evidence close the callback gates. Read back its exact redirect and flags, verify private file mode, and confirm no OAuth state or candidate was generated. Label the result **ready for private consent**, not reauthorized or publication-ready; stop before invoking the interactive start/finish helpers. An isolated nginx syntax test may need writable prefix-local temp paths; passing it does not prove the public callback works. Use dummy query parameters for callback tests, never a real authorization code.

If blocked, save the repair, verification results and precise operator action, and stop without generating a code. After genuine consent and successful promotion, resume read-only job reconciliation; any publication still requires its own exact-content approval.
